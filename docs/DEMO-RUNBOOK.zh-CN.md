# Adventure 演示与上线手册

## 结论

- `prepared_demo` 已经可以在单机、无网络、无 Discourse、无模型密钥的条件下完整演示。
- 该模式使用隔离的临时数据库和经过完整性校验的预置产物。Studio 试跑和 Arena 成绩都会明确标记为预置、非官方、未调用 AI。
- 当前代码还不能直接作为“开放注册、真实社区、正式排行榜”的公网产品上线。生产环境需要补齐 ADVX 前端打包、登录页面、账号发放、外部 PostgreSQL、模型凭据、Discourse/Profile Bridge 以及反向代理。

## 演示前启动

环境要求：Node.js 20+、pnpm 9.15+。

```powershell
pnpm install --frozen-lockfile
pnpm advx:demo -- --profile prepared_demo --reset
```

命令会自动选择端口并打开 `/demo`。看到终端输出 `ADVX demo ready` 后再开始讲解。演示期间不要关闭该终端；按 `Ctrl+C` 会停止服务并删除本次临时数据库。

单独做一次启动验收，可运行：

```powershell
pnpm advx:demo -- --profile prepared_demo --check --no-open
```

注意：`--check` 验收完成后会主动关闭并清理自己的临时实例，它不是正式的演示启动命令。

## 推荐的 8 分钟点击路线

### 1. Studio：队长组建 AI 队伍

1. 打开 `/demo`，页面会自动进入 `/studio`。
2. 介绍 `Todo Makers` 和侦察员、点子员、搭建员、挑刺员四个起步角色。
3. 点击任意角色卡片，展示职责和工具配置，再返回 Studio。
4. `Reflection Coach` 和 `Summarizer` 是系统辅助角色，不属于四角色起步队伍，现场只需一句带过。

建议话术：孩子不是在使用一个聊天框，而是在配置一支有分工、有工具、有版本历史的 AI 队伍。

### 2. 试跑：展示队伍产物闭环

1. 点击 `试跑一次`。
2. 选择 `做个待办清单`，点击 `开始试跑`。
3. 确认任务后点击 `启动`。
4. 在结果页展示状态、活动记录和 `预置 Todo 演示产物`。

建议话术：演示模式会稳定返回经过校验的预置产物，不依赖现场网络；页面会如实标注本次没有调用 AI，也不声称产物由本次试跑生成。

### 3. Arena：展示评分与证据

1. 顶部点击 `赛题`。
2. 在 `会记住的待办清单` 中点击 `查看详情`。
3. 点击 `查看成绩`。
4. 展示 `894 / 1000`、八个评分维度、双评委分数、仲裁结果和源码行证据。

建议话术：正式 Arena 会使用受保护的模型配置；当前是非官方演示评分，重点展示可追溯的评分机制，而不是冒充真实比赛成绩。

### 4. 排行榜：只展示界面概念

1. 顶部点击 `排行榜`。
2. 展示当前队伍第 2 名、894 分以及移动端可横向阅读的表格。

必须说明：这里是本地样例榜单，不是真实用户数据，也不是当前正式产品承诺。现有产品边界仍禁止公开 Arena 分数和公开排名。

### 5. 社区：展示本地替身

1. 顶部点击 `论坛`。
2. 切换作品展示、制作日志、互助问答。
3. 搜索主题、展开讨论、点击收藏。

必须说明：演示页面由本地 Demo API 提供。真实社区是独立的 Discourse 服务，需要 SSO、Profile Bridge 和儿童安全插件，本仓库当前不包含该论坛工程。

### 6. 我的：展示身份与隐私

1. 顶部点击 `我的`。
2. 点击 `设置`，展示昵称和三项隐私控制。
3. 点击 `联系人`，展示联系人管理入口。

必须说明：演示模式只有一个本地队长身份，联系人列表为空；真实联系人和私信需要多个已登录账号以及 Discourse 授权关系。

## 当前能力矩阵

| 能力 | 本地演示 | 生产状态 |
| --- | --- | --- |
| Studio 队伍、成员、工具、版本、活动 | 可演示，使用真实 API 和临时 PostgreSQL | 业务逻辑已具备 |
| Studio 试跑 | 预置结果可稳定跑通 | 真实执行需要模型适配器和密钥 |
| Arena 上传、进度、结果、证据 | 预置非官方评分可稳定跑通 | 正式评分需要受保护的 DeepSeek 配置；当前只支持单服务进程 |
| 排行榜 | 本地样例数据 | 没有正式多人榜单，当前产品边界不允许公开排名 |
| 社区 | 本地社区替身 | 需要独立 Discourse、Profile Bridge、SSO 和安全插件 |
| 个人设置、联系人 | 单用户演示接口 | 多用户逻辑存在，但外部桥接和真实账号验收未完成 |
| 新用户入驻 | 不适用 | 未完成。儿童模式只开放登录，不开放自助注册；ADVX 前端也没有登录/注册页 |
| Docker 公网部署 | 不用于 prepared demo | 当前 Dockerfile 构建的是旧 `ui/`，不是 `ui-advx/`，需要专门的生产镜像或静态站部署 |

## 公网上线的正确拓扑

```text
浏览器
  -> HTTPS 反向代理
       -> ui-advx 静态文件
       -> /api/*            Adventure API
       -> /discourse/*      Discourse

Adventure API
  -> PostgreSQL
  -> 持久化文件或 S3
  -> 受保护的模型提供方
  -> 内网 Profile Bridge

Discourse
  -> 自己的 PostgreSQL / Redis
  -> TeenX 安全插件和主题
  -> Discourse Connect SSO
```

生产环境不能使用 `prepared_demo`。该配置会拒绝非本机、生产或不安全的启动方式。

## 公网上线前必须完成

1. 把当前本地改动提交并推送到私有 `adventure` 仓库。
2. 新增生产构建，让 `ui-advx` 成为对外前端；生产反向代理复刻 Vite 开发代理中的 `/api`、`/discourse` 和 SSO 路由。
3. 使用外部 PostgreSQL 和持久化对象存储，配置备份与恢复。
4. 使用 `authenticated + public`、HTTPS、强 `BETTER_AUTH_SECRET`，并启用 `TEENX_CHILD_MODE=true`。
5. 新增 ADVX 登录页和受控账号发放流程。若需要自助注册，必须先重新审计儿童模式 allowlist、监护人/邀请/年龄规则，不能直接开放 Better Auth 的注册接口。
6. 配置真实模型适配器；正式 Arena 还要配置精确匹配的受保护 DeepSeek 评审凭据。
7. 找回或重新建立独立的 `teenx-forum` 仓库，部署 Discourse、Profile Bridge、儿童安全插件和 SSO 密钥迁移。
8. 对多用户隔离、联系人同意、屏蔽、私信撤销、隐私字段、上传限制和速率限制做一次真实公网验收。
9. 决定是否真的要做排行榜。若要做，需要新的产品与安全授权、正式赛事数据模型、反作弊、隐私规则和公开成绩 API，不能把 Demo fixture 直接改成生产榜单。

## 最终判断

现在可以放心做“产品能力演示”，但不能宣称已经是可接受陌生用户注册的生产社区。部署一台普通服务器只会让现有服务能被访问，不会自动补齐 Discourse、账号入驻、真实模型、正式排行榜和多用户运营能力。
